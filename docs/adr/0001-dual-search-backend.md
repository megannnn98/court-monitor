# Два независимых поисковых backend'а вместо одного

Проекту нужен и точный поиск по словоформам (юридические термины, ФИО, названия статей УК), и семантический поиск по смыслу запроса. Вместо того чтобы выбрать одну технологию, реализованы два независимых backend'а — `PostgresLexicalSearch` (tsvector/GIN в той же Postgres, где уже лежат данные) и `QdrantDenseSearch` (векторный поиск в Qdrant по эмбеддингам `sentence-transformers`) — за общим протоколом `SearchBackend`, с выбором через `--backend` в CLI. Это дороже в эксплуатации (два хранилища, два индекса, которые надо синхронизировать через `QdrantChunkIndexer.index_all()`), но позволяет сравнивать качество lexical vs dense на одних и тех же `EvaluationCase` (см. `reports/postgres_lexical_baseline.json` и `reports/qdrant_dense_baseline.json`) прежде чем закладывать одну технологию как единственную. Расширение Postgres до `pgvector` не рассматривалось как замена — по документации не было, оно решило бы только dense-часть и не убрало бы необходимость во втором индексе/синхронизации.
