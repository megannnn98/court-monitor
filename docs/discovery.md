## 2. Платформа sudrf.ru (ГАС «Правосудие»)

### 2.1. Подтверждённые факты

- Главный портал `https://sudrf.ru/` отвечает **200** на plain HTTP-запрос.
- Шаблон URL судов: `https://<sub>.sudrf.ru/` (один поддомен на суд).
- Платформа использует движок `index.php?id=<NNN>` (классический pattern
  ГАС «Правосудие»). Найденные ссылки с главной:
  `/index.php?id=300`, `/index.php?id=300&var=true`.
- Сопутствующие подсистемы той же платформы:
  - `bsr.sudrf.ru` — Банк решений судов (решения по делам).
  - `docs.sudrf.ru`, `techportal.sudrf.ru` — тех. порталы.
- `robots.txt` на court-поддомене разрешает всё (`User-agent: * / Allow: /`).
- На военных судах массово используются модули `press` (пресс-релизы),
  `sud_delo` (карточки дел), `sud_practice` (судебная практика) — это
  известная структура платформы, но **пути нужно подтверждать per-court**.

### 2.2. Поддомены военных судов — текущая доступность

Из текущего окружения (Linux, исходящий IP, UA `CourtMonitorBot/0.1`):

| Поддомен | `GET /` | `robots.txt` | `www.` / `m.` | Вывод |
|---|---|---|---|---|
| `2zovs.sudrf.ru` | **404** (26 KB страница) | есть (200) | SSL mismatch | хост жив, корень не отдаёт контент |
| `uovs.sudrf.ru` | **404** | — | — | аналогично |
| `sudrf.ru` (главный) | **200** | — | — | работает |

404 на корне при живом `robots.txt` означает одно из:

1. сайт суда переведён на специфический путь (модуль `press`/`sud_delo`)
   и корень намеренно не отдаёт контент;
2. сервер отдаёт 404 по UA/гео/антибот-эвристике (для «чужих» UA);
3. сайт суда физически отключён/реструктуризован.

Какую именно причину — **из этого окружения определить нельзя**. Это
нормальное ограничение Discovery: архитектура обязана быть устойчивой к
тому, что live-доступ к конкретному суду может отсутствовать или быть
нестабильным.

### 2.3. Архитектурное следствие (важно)

- **Fixtures-first design.** Парсеры разрабатываются и тестируются на
  сохранённых HTML-снимках (`tests/fixtures/html/...`), а не на live-сети.
  Это также требуется спекой (regression fixtures).
- **Политый HTTP-клиент** (httpx + tenacity + ETag/Last-Modified) — основной
  способ. **Playwright** — только fallback для JS-страниц.
- **Адаптер настраивается per-court через YAML** (базовый URL, пути модулей,
  селекторы). Если сайт меняет структуру — правится конфиг+парсер, а не код.
- **CAPTCHA не обходится.** При признаках блокировки адаптер переходит в
  статус `source_blocked` и создаёт `ReviewItem` оператору.
- **Live-пробы конкретного суда** переносятся в этап 2 — после получения
  от оператора подтверждённого рабочего URL/пути суда (возможно, из сети,
  где сайт отвечает нормально).

## 3. Росфинмониторинг (Перечень террористов)

### 3.1. Что известно

- Официальный издатель: `fedsfm.ru` (Федеральная служба по финансовому
  мониторингу).
- Перечень физических лиц публикуется в виде HTML/XLS/ZIP на странице
  «Реестр террористов». Несколько документов (по дате обновления).
- Запись содержит: ФИО, дату рождения, место рождения, иногда
  «звёздочку» (отметка об отсутствии данных/особая категория).

### 3.2. Текущая доступность из окружения

- `https://www.fedsfm.ru/` — **SSL-сертификат не валидируется** в этом
  окружении (`unable to get local issuer certificate`).
- `http://fedsfm.ru/` → 301 на `https://fedsfm.ru/`.

Это окруженческая проблема (корневые сертификаты), а не блокировка. В
production-контейнере (на базе актуального CA-bundle) валидация должна
работать. До подтверждения работаем с **сохранённым снимком перечня** как
fixture, а live-импорт реализуем параметризуемо (URL списка документов —
в конфиге).

### 3.3. Архитектурное следствие

- Импортёр РФМ — отдельный адаптер: скачивает файл, парсит строки,
  нормализует ФИО (через общий `normalization`-модуль), сохраняет запись с
  `first_seen / last_seen / removed_at` и историей изменений.
- «Звёздочка» хранится как **отдельный признак источника**, не как
  доказательство статьи УК (требование спеки §3.4, §4.2).

|---|---|---|---|

каркас страницы, **названия таблиц/колонок/типы/связи программно не
извлекаются**. Это сознательное ограничение Airtable; обходить его
запрещено спекой (§4.3, §30.5).

**Режим до получения PAT — mock-адаптер**, отражающий заявленную в спеке
доменную модель (`Persons`, `Cases`, `CourtEvents`, `Sources`, …).

## 5. Telegram

- Вспомогательный источник. По умолчанию все факты из Telegram —
  `verification_status = unverified`.
- На этапе MVP не реализуем live-импорт (требует MTProto-credentials и
  аккуратного соблюдения ToS). Реализуем **импорт экспортированного JSON**
  (официальный export Telegram) — этого достаточно для тестирования
  пайплайна. Live-импорт — Etap 10+.

## 7. Предлагаемая доменная модель (стартовая)

Внутренние модели реализуются SQLAlchemy 2 + Pydantic v2. Состав — по спеке
§13, с уточнениями из Discovery:

- `Person`, `PersonAlias`
- `Case`, `PersonCase` (роль, статус связи, уверенность, источник)
- `CourtEvent`
- `SourceDocument` (URL, тип, дата публ./загрузки, HTTP-статус, контент,
  хеш, путь к копии, версия парсера)
- `ExtractedFact` (сущность, поле, значение, `verification_status`,
  confidence, цитата, источник, способ извлечения) — реализует §3.1
- `ReviewItem` (тип предложения, приоритет, данные, кандидаты, объяснение,
  статус, оператор, решение, комментарий)
- `AuditLog` (actor, действие, объект, old, new, correlation_id)
- `RfmEntry` + `RfmEntryHistory` (first_seen/last_seen/removed_at)

Ключевое правило (§3.1, §3.2): любое значение поля — это `ExtractedFact` со
статусом, цитатой и source_id. «Подтверждённый факт» — только
`verification_status = confirmed` с надёжным источником.

Подробно — в `docs/data-model.md` (будет создан на Etap 1).

- GitHub Actions: ruff, format check, mypy, pytest, build
- базовые тесты + fixtures-каталог

### Etap 2 — Первый источник (sudrf.ru, fixtures-first)

- `sources/base.py`: абстрактный `SourceAdapter` + `FetchResult`
- httpx-клиент: UA, delay, concurrency-per-host, retry (tenacity), timeout,
  ETag/Last-Modified, кеш, dedup URL, сохранение HTML, hash, статус
  `parser_failed` / `source_blocked`
- `sources/sudrf.py`: generic-адаптер платформы, конфиг per-court
- парсер пресс-релиза: заголовок, дата, текст, релевантность
- сохранение `SourceDocument`, дедупликация (canonical URL + text-hash)
- CLI: `fetch-source <name>`, `parse-pending`
- тесты на сохранённых HTML-fixtures (обезличенных/публичных образцах)

### Etap 3 — Извлечение

- `extraction/`: статьи УК (regex), даты, ФИО, регион, тип события,
  наказание — каждый возвращает `ExtractedFact` с цитатой/confidence
- Pydantic-схемы валидации (§6.1, §6.2)
- LLM-интерфейс (§7): `LlmExtractor` Protocol, OpenAI-совместимый
  провайдер, Ollama, отключаемый режим. LLM-ответ валидируется схемой.
- `normalization`: ФИО (§8)
- CLI: `parse-pending` углублён; unit-тесты на все экстракторы

## 9. MVP-критерий для этого среза

Минимальный вертикальный срез, который будет реализован после
подтверждения плана:

```
пресс-релиз суда (fixture)
  → загрузка/чтение документа
  → сохранение SourceDocument (HTML, hash, дедупликация)
  → извлечение заголовка + даты
  → фильтр по статье/ключевику (conf yaml)
  → запись ExtractedFact(-ов)
  → вывод результата через CLI (court-monitor parse-pending / show)
  → unit-тесты + integration-тест на fixtures
  → ruff/format/mypy/tests green
```

Live-сеть **не требуется** для прохождения проверок — всё на fixtures. Это
соответствует требованию «система должна оставаться запускаемой и
протестированной после каждого этапа».
