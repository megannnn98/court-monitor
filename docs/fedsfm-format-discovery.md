## Форматы файлов

### 1. Перечень экстремистов/террористов — DBF

Файл: `terrorists.dbf` (или类似ное имя)
Кодировка: CP866 (DOS) или Windows-1251
Структура записи (по документации 1С-Рарус):

| Поле DBF | Тип | Описание | → PersonRecord |
|---|---|---|---|
| `FIO` | Char(250) | ФИО | `raw_name` |
| `BIRTHDAY` | Date | Дата рождения | `birth_date` |
| `BIRTHPLACE` | Char(250) | Место рождения | `birth_place` |
| `REASON` | Char(250) | Основание включения | `category` |
| `DATE_ADD` | Date | Дата включения | `added_date` |
| `NUM` | Char(50) | Номер записи | `source_ref` |

Примечания:
- ФИО в верхнем регистре (ИВАНОВ ИВАН ИВАНОВИЧ)
- Дата в формате DBF Date (8 байт, YYYYMMDD)
- Кодировка зависит от настройки системы

### 2. Перечень экстремистов/террористов — XML

Файл: `terrorists.xml`
Кодировка: UTF-8 (с XML declaration)
Структура (на основе Приказа №134):

```xml
<?xml version="1.0" encoding="utf-8"?>
<Файл>
  <СвФЛ>
    <ФИО>Иванов Иван Иванович</ФИО>
    <ДатаРожд>01.01.1980</ДатаРожд>
    <МестоРожд>г. Москва</МестоРожд>
    <Основание>Причастность к экстремистской деятельности</Основание>
    <ДатаВключ>2020-03-15</ДатаВключ>
    <НомерЗап>1</НомерЗап>
  </СвФЛ>
  ...
</Файл>
```

Примечания:
- Теги на русском языке
- Даты в формате DD.MM.YYYY или YYYY-MM-DD
- Кодировка UTF-8

### 3. Перечень МВК (замораживание средств) — XML

Аналогичная структура, но с дополнительными полями:
- `ИНН` (ИНН физического лица)
- `ОГРН` (для организаций)

### 4. ZIP-архивы

По FAQ АРМ СК РФМ:
- ZIP может содержать XML или DBF
- ZIP может быть просто переименованным XML (особенно для перечня ООН EN)
- Нужно проверять содержимое архива

## Неизвестные/неоднозначные поля

1. **Точная структура XML** — нет доступа к реальному файлу, теги могут отличаться
2. **Кодировка DBF** — может быть CP866 или Windows-1251
3. **Формат дат** — DD.MM.YYYY или YYYY-MM-DD или DBF Date
4. **Наличие заголовков** — XML может иметь атрибуты в корневом теге
5. **Множественные записи** — один файл может содержать несколько перечней

## Ограничения

- Прямой доступ к portal.fedsfm.ru требует авторизации (сертификат ЭЦП)
- SSL-сертификат fedsfm.ru не валиден в текущем окружении
- Оператор должен скачать файл вручную и передать через `--file`

## Рекомендации для реализации

1. Поддержать XML, DBF, ZIP, CSV (внутренний формат)
2. Для XML: парсинг через ElementTree, поиск тегов по шаблону
3. Для DBF: использовать библиотеку `dbfread` (Pure Python)
4. Для ZIP: распаковка в temp, определение формата содержимого
5. Кодировка: автоопределение (chardet) или fallback на CP866/UTF-8
6. Dry-run: парсинг без записи в БД
