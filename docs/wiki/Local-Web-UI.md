# Local Web UI / «Следователь»

## Зачем это нужно

Операторская консоль живёт в том же FastAPI-приложении, что и JSON API, и
построена вокруг расследования конкретного человека: кто это, в каком деле он
фигурирует, что и когда произошло, на каких публикациях основан вывод системы,
почему дело признано политическим, есть ли человек в перечне Росфинмониторинга и
что требует ручной проверки. Аутентификации нет: API публикуется только на
`127.0.0.1` (ADR 0014).

## Быстрый сценарий

Открыть <http://127.0.0.1:8001/> — откроется «Работа».

Типичный день оператора:

1. «Работа»: нажать «Сделать всё», затем открыть следующую станцию проверки с
   ненулевым счётчиком ([Pipeline](Pipeline.md)).
2. «Результат»: политические дела; период (дни в формате дд/мм/гггг) и выгрузка в
   Excel.
3. Имя человека → досье: проверить решение системы по цитатам.
4. «Пары», «Роль», «Политичность»: отдельные проверки между шагами.
5. «Безымянные»: опознать фигурантов без имени по перечню; результат обновится
   после следующих шагов 3–5
   ([Unnamed Figurants](Unnamed-Figurants.md)).

## Разделы

Меню делится на три группы:

| Группа | Пункты |
|---|---|
| Каждый день | Работа · Результаты · Найти человека |
| Данные | Все люди · Публикации · Перечень РФМ · База Airtable |
| Система | Журнал запусков · Логи · Вики · О системе |

Остальные страницы из таблицы ниже в меню не стоят: на них ведут ссылки с других страниц.

На телефоне (экран уже 860 px) меню заменяет панель внизу экрана: «Работа», «Результаты»,
«Найти» и «Ещё». «Ещё» открывает над панелью группы «Данные» и «Система». Пока идёт шаг,
над панелью на каждой странице стоит строка «Идёт: …» со ссылкой на ход запуска, а кнопка
«Сделать всё» или «Остановить» на «Работе» держится у нижнего края, пока её блок на экране.

| Раздел | Адрес | Что там |
|---|---|---|
| Работа | `/ui/cycle` (сюда ведут `/` и `/ui`) | пять шагов и проверки между ними; текущее состояние, последний итог, единая подсказка «Дальше» |
| Результат | `/ui/political` | фигуранты с политическими делами; столбец «Перечень РФМ» с датой рождения и местом; период по дате последней новости; Excel `result_<с>_<по>.xlsx` |
| Обзор | `/ui/overview` | новые дела, приговоры и безымянные фигуранты |
| Найти человека | `/ui/investigations`, `/ui/investigations/{key}` | поиск человека; досье |
| Все люди | `/ui/entities` | все люди: фильтры по роли, вердикту, региону, статье УК, перечню; сортировка по столбцам; строка открывает досье |
| Безымянные | `/ui/unnamed` | фигуранты без имени и кандидаты на них: из перечня (в том числе исключённые из него), из базы Airtable, из других публикаций |
| Без имени в базе | `/ui/base-unnamed` | записи базы Airtable без имени и кандидаты на них из перечня, в том числе исключённые из него |
| Перечень РФМ | `/ui/rfm`, `/ui/rfm?removed=1` | перечень по последнему снимку, фильтр по дню включения, Excel; исключённые из перечня по таблице оператора ([Rosfinmonitoring](Rosfinmonitoring.md)) |
| База Airtable | `/ui/airtable` | синхронизация списков оператора, обновление перечня, должностные лица ([Airtable Sync](Airtable-Sync.md)) |
| Публикации | `/ui/publications`, `/ui/articles/{id}` | поиск по заголовку и тексту, фильтр по источнику; люди и события каждой публикации; полный текст с подсветкой |
| Пары | `/ui/pairs` | спорные совпадения, решения «Один человек» / «Разные люди» |
| Роль | `/ui/roles` | случаи, где шаг 4 не определил роль; решение «Фигурант» / «Задержан или обыскан» / «Только упомянут» |
| Политичность | `/ui/politics-review` | случаи, где шаг 5 не определил политичность; решение «Политическое» / «Обычное уголовное» |
| Система → Журнал запусков | `/ui/runs` | сверху вниз: запуск («Сделать всё», шаги, даты шага 1), карточка запуска, история, ошибки источников, воронка отбора (`#funnel`) |
| Должностные лица | `/ui/officials` | кто отмечен судьёй, прокурором, следователем; снять отметку |
| Система → Логи, Вики | `/ui/logs`, `/ui/wiki` | лог запусков; эта вики и её PDF |

Старые адреса работают: `/ui/queue` и `/ui/disputes` ведут на `/ui/pairs`,
`/ui/management` — на `/ui/runs`, `/ui/entities/{key}` — в досье.

## Досье человека

`/ui/investigations/{key}`, где `key` — ключ сущности («александр моор»).

- **Заголовок**: имя фамилией вперёд, как писали, регион, число публикаций, первая
  и последняя публикация, события дела, роль, вердикт, статус перечня, спорные
  пары. «Исправить имя и ручные решения» — исправить имя, отметить или снять
  «должностное лицо».
- **Решение системы**: вердикт с причиной, цитатой и ссылкой на исходную
  публикацию; роль с причиной; совпадения с перечнем (ФИО, дата рождения, место);
  ограничения. Уверенность модели не хранится — страница так и пишет.
- **Статьи УК**: статья, части, «политическая», «общая» (в событии обвиняемыми
  названы и другие люди), число публикаций.
- **Хронология**: события, где человек назван участником; события одного типа в
  один день из разных публикаций — одна строка с несколькими источниками. Дата —
  дата публикации, так и подписано.
- **Граф событий**: интерактивный граф — человек, его события, а у раскрытого события его
  люди, публикация, суд, орган и статьи ([Investigation Graph](Investigation-Graph.md)).
  Под ним таблица «Люди из тех же публикаций»: это счёт совместных упоминаний, не связь.
- **Доказательства**: публикации с подсвеченным упоминанием, источник, дата,
  внешняя ссылка, события, статьи и другие люди.

## Проверки рабочего цикла

- **Спорные пары** показывают обе стороны, варианты имён, регионы,
  статьи, события, общие публикации, почему пара предложена и почему не слита
  автоматически. «Один человек» и «Разные люди» сохраняются как ручное решение
  (`entity_pair_decisions`, `source = manual`) и применяются при каждой пересборке;
  затем исчезают из открытых пар.
- **Сбросить все решения по парам** удаляет все решения, ручные и автоматические,
  после подтверждения. «Разные люди» возвращаются сразу; слитые люди разделятся
  при следующей сборке сущностей (шаг 3). Необратимо.
- **Роль** и **политичность** — решения оператора: «Фигурант» / «Задержан или
  обыскан» / «Только упомянут» и «Политическое» / «Обычное уголовное». Решение
  сохраняется по ключу сущности (`entity_role_decisions`,
  `entity_politics_decisions`) и применяется при каждой пересборке шага 4 или 5;
  решённый случай исчезает из списка.
- **Сбои извлечения** информационные и находятся в журнале запусков; они не входят
  в счётчик открытых решений.

## Интерфейс

- Под заголовком каждой страницы — кнопка «Как это работает»: пояснение и
  следующее действие.
- Светлая и тёмная тема — по настройке системы.
- На телефоне меню открывается кнопкой в верхней панели; таблицы прокручиваются
  внутри себя, имя в «Людях» остаётся на месте.
- «К содержанию», видимая рамка фокуса, подписи полей и таблиц.
- Нумерация страниц: «Назад · 1 · … · 12 13 14 · … · 248 · Вперёд», фильтры
  сохраняются.
- Имена — фамилией вперёд («Иванов Иван Петрович»).

Для диаграмм вики в образ ставятся `plantuml` и `graphviz`. Локально
(`uv run`) нужны те же пакеты: `sudo pacman -S plantuml graphviz`. PDF вики
(`/ui/wiki/export.pdf`) собирается ~15 с.

## Ограничения и типичные ошибки

- Страницы только читают, кроме форм: шаги pipeline, решения по парам и
  безымянным, исправление имени, отметка должностного лица, сброс решений.
- Счётчик рабочего цикла в меню пересчитывает спорные пары по всей базе на каждой
  странице.
- JSON API (`/persons`, `/articles`, `/operations/runs`, …) консоль не
  меняет; он остаётся контрактом для автоматизации.

## Удобства оператора (01.10.2026)

Сделаны по просьбам оператора; страницы работают и без них.

- **Место в списке сохраняется.** После любой кнопки, которая перезагружает страницу
  («Мусор», галочка «обработано»), страница открывается там же, где была, а не сверху.
- **Внешние ссылки открываются в новой вкладке** — источники и публикации.
- **Кнопка копирования у имени** в «Результате», досье и «Перечне».
- **Галочка «обработано» в «Результате».** Отмеченный человек уходит из списка и из
  выгрузки Excel. Отметка хранится по ключу человека (`entity_done_marks`) и переживает
  пересборку. Она помнит дату последней новости на момент отметки: появится новость
  позже — человек вернётся в список сам. Флажок «Показать обработанных» рядом с фильтрами возвращает их в
  список, повторный клик по галочке снимает отметку.
- **Повторы в «Отсеве».** Удержанные публикации об одном и том же стоят вместе, с кнопкой
  «Мусор — все N». Повтором считается общий человек (имя и фамилия, как их привело
  извлечение) или почти одинаковый заголовок (`TITLE_SIMILARITY`). Это догадка, а не
  доказательство: ничего не объединяется и не удаляется само, у каждой публикации
  остаются свои кнопки. Одной фамилии для повтора мало. Имя в разных падежах («Александра
  Кынева» и «Александр Кынев») может не совпасть — тогда публикация останется отдельно.

Скрипт — `src/static/local-ui.js`.

## Сортировка таблиц (05.10.2026)

Любая таблица сортируется нажатием на заголовок столбца; второе нажатие меняет порядок,
стрелка в заголовке показывает направление. Числа, даты вида 05.10.2026 и слова
сравниваются каждое по-своему, пустые ячейки всегда в конце.

Сортируются строки, которые есть на странице. Там, где показана часть списка
(«Результат», «Публикации», «Перечень РФМ» — первые 100), упорядочивается эта часть, а не
весь список. «Все люди» сортируются сервером по всему списку, как и раньше.

Код — `src/static/table-sort-core.js` (порядок, проверяется тестами под node) и
`src/static/table-sort.js` (заголовки и строки).

## Журнал запусков (05.10.2026)

`/ui/runs` идёт в порядке «запустить → что идёт → чем кончилось»:

1. **Запуск.** «Сделать всё», пять кнопок шагов; под ними свёрнутая строка «Ограничить
   даты публикаций для шага 1».
2. **Карточка запуска** — идущего или последнего. Числа итога стоят строками с подписью:
   у шага 5 — «Вердикты», «Перечень РФМ», «Свежие новости», «Модель и расход»; у шагов 3
   и 4 — «Итог» и «Модель и расход». Пустая строка не показывается.
3. **Последние ручные запуски.**
4. **Ошибки источников.**
5. **Воронка отбора** (`#funnel`) — за всё время, не за запуск; сюда ведёт «Подробнее» со
   страницы «Результат».

Код — `_management_page` в `src/web/ui/management.py`, строки карточек — `_summary` в
`src/web/ui/run_cards.py`.

## Расходы, прогресс и выгрузка людей (01.10.2026)

- **Баланс и предупреждения о трате.** Четыре шага цикла спрашивают платную модель через
  OpenRouter: очистка (Jev, около $0,00006 за статью), «Собрать сущности», «Найти фигурантов»
  и «Политические дела» (DeepSeek, не более `ENTITY_MODEL_BUDGET_USD`, по умолчанию $2, за
  запуск). Перед шагом — на «Работе» и в «Журнале запусков» — стоит строка «Шаг платный…» с остатком
  на счёте; то же остаток в окне подтверждения и на карточке идущего шага; красным, если
  остатка меньше лимита запуска. Остаток — купленное минус потраченное
  (`GET openrouter.ai/api/v1/credits`; `/api/v1/key` — лимит самого ключа, а не баланс), ответ
  кэшируется на минуту, ожидание 4 с. Нет ключа — строк нет; нет ответа — «Баланс OpenRouter
  сейчас узнать не удалось». Код — `src/web/ui/spend.py`.
- **Сколько потратил запуск (07.10.2026).** Каждый платный шаг печатает цену своих вызовов
  модели в итогах запуска, а журнал запусков хранит итоги. Поэтому история трат — это
  история запусков:
  - под карточкой запуска — «Этот запуск потратил на модель $…» и «Предыдущий запуск этого
    шага (#…, дата): $…»;
  - в строке «Шаг платный…» перед шагом — «В прошлый раз шаг потратил $…»;
  - в «Журнале запусков» — колонка «Потрачено на модель» и свёрнутый блок «Расходы на
    модель по запускам» по последним 20 платным запускам с итогом.

  Запуск, который остановили или который упал, итогов не напечатал: его расход показан как
  «неизвестно», а не как ноль. Вопросы страницы «Спросить» и запуски из командной строки в
  журнал запусков не попадают. Очистка считает и цену самого отсева (`screen_cost_usd`):
  её сообщает модель в каждом ответе.
  Остаток стоит и в полосе показателей наверху каждой страницы: плашка «Баланс OpenRouter»
  в конце строки, красная, когда остатка меньше лимита запуска; чёрточка — OpenRouter не
  ответил; без ключа плашки нет.
- **Этапы «Политических дел».** Шаг идёт в пять этапов: сверка с перечнем, политичность,
  сводки новостей, свежая новость, безымянные. На карточке — «Этап N из 5 · …: сделано из
  всего» с полосой для каждого этапа, где модель читает тексты. Сверка с перечнем длится
  секунды и идёт без полосы, с подписью этапа.
- **Пульс и три строки журнала на каждой странице идущего шага.** Под идущим шагом — на
  «Работе», на карточке «Журнала запусков» и на странице «Все люди» во время сборки — стоят две вещи:
  когда процесс в последний раз подал сигнал («Процесс отвечает: последний сигнал 20 с
  назад»; ранний признак зависания — сигнал старше пяти минут, после чего запуск сам
  отмечается потерянным) и три последних события журнала: по одной, самой свежей, строке на
  событие, без даты, уровня и шума запросов. Пока процесс ничего не написал, страница так и
  говорит. У упавшего или остановленного шага остаются последние строки, у успешного — ничего.
  Полный журнал — по ссылке «Лог запуска». Код — `src/web/ui/run_tail.py`.
- **Выгрузка всей базы людей.** Кнопка «Выгрузить всех людей в Excel» на странице «Все люди»,
  `GET /ui/people/export.xlsx`: без фильтров, лист «Люди» (все с именем: роль, дело, статьи,
  регион, последняя и свежая новость, перечень РФМ, база Airtable, «обработано»), лист «Без
  имени» (все не опознанные безымянные случаи, не только политические) и «Пояснения» с
  атрибуцией ОВД-Инфо. Пустая ячейка роли или дела — шаг ещё не определял.
