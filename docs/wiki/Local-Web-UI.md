# Local Web UI / «Следователь»

## Зачем это нужно

Операторская консоль живёт в том же FastAPI-приложении, что и JSON API, и
построена вокруг расследования конкретного человека: кто это, в каком деле он
фигурирует, что и когда произошло, на каких публикациях основан вывод системы,
почему дело признано политическим, есть ли человек в перечне Росфинмониторинга и
что требует ручной проверки. Аутентификации нет: API публикуется только на
`127.0.0.1` (ADR 0014).

## Быстрый сценарий

Открыть <http://127.0.0.1:8001/> — откроется «Обзор».

Типичный день оператора:

1. «Обзор»: новые фигуранты, очередь, состояние цикла из шести шагов; кнопка
   текущего шага запускает его ([Pipeline](Pipeline.md)).
2. «Результат»: политические дела; период (дни в формате дд/мм/гггг) и выгрузка в
   Excel.
3. Имя человека → досье: проверить решение системы по цитатам.
4. «Очередь»: спорные пары, неясные роли и вердикты, сбои извлечения.
5. «Безымянные»: опознать фигурантов без имени по перечню
   ([Unnamed Figurants](Unnamed-Figurants.md)).

## Разделы

| Раздел | Адрес | Что там |
|---|---|---|
| Обзор | `/ui/overview` (сюда ведут `/` и `/ui`) | показатели, новые фигуранты, очередь, шесть шагов с кнопкой текущего, ошибки источников; таблицы запусков и воронка — свёрнуты |
| Результат | `/ui/political` | фигуранты с политическими делами; столбец «Перечень РФМ» с датой рождения и местом; период по дате последней новости; Excel `result_<с>_<по>.xlsx` |
| Расследование | `/ui/investigations`, `/ui/investigations/{key}` | поиск человека; досье |
| Люди | `/ui/entities` | все люди: фильтры по роли, вердикту, региону, статье УК, перечню; сортировка по столбцам; строка открывает досье |
| Безымянные | `/ui/unnamed` | фигуранты без имени и кандидаты на них из перечня |
| Публикации | `/ui/publications`, `/ui/articles/{id}` | поиск по заголовку и тексту, фильтр по источнику; люди и события каждой публикации; полный текст с подсветкой |
| Очередь | `/ui/queue` | спорные пары по одной, неясные роли, неясная политичность, сбои извлечения, число неразобранных безымянных |
| Система → Управление | `/ui/management` | шесть шагов, карточка запуска, история запусков, воронка отбора |
| Система → Должностные лица | `/ui/officials` | кто отмечен судьёй, прокурором, следователем; снять отметку |
| Система → Логи, Вики | `/ui/logs`, `/ui/wiki` | лог запусков; эта вики и её PDF |

Старые адреса работают: `/ui/entities/{key}` ведёт в досье (307), `/ui/disputes`
— прежний список спорных пар.

## Досье человека

`/ui/investigations/{key}`, где `key` — ключ сущности («александр моор»).

- **Заголовок**: имя фамилией вперёд, как писали, регион, число публикаций, первая
  и последняя публикация, события дела, роль, вердикт, статус перечня, спорные
  пары. «Исправить имя и ручные решения» — исправить имя, отметить или снять
  «должностное лицо».
- **Решение системы**: вердикт с причиной, цитатой и ссылкой на исходную
  публикацию; роль с причиной; совпадения с перечнем (ФИО, дата рождения, место);
  ограничения. Уверенность модели не хранится — страница так и пишет.
- **Статьи УК**: статья, части, «политическая», «общая» (в событии обвиняемыми
  названы и другие люди), число публикаций.
- **Хронология**: события, где человек назван участником; события одного типа в
  один день из разных публикаций — одна строка с несколькими источниками. Дата —
  дата публикации, так и подписано.
- **Связи**: SVG-граф до 18 узлов (статьи, люди из тех же публикаций, суды и
  органы, публикации, события), рядом — тот же список таблицей. Только связи из
  данных, без сходства по смыслу. На телефоне — только список.
- **Доказательства**: публикации с подсвеченным упоминанием, источник, дата,
  внешняя ссылка, события, статьи и другие люди.

## Очередь

- **Спорные пары** показываются по одной: обе стороны, варианты имён, регионы,
  статьи, события, общие публикации, почему пара предложена и почему не слита
  автоматически. «Один человек» и «Разные люди» сохраняются как ручное решение
  (`entity_pair_decisions`, `source = manual`) и применяются при каждой пересборке;
  затем открывается следующая пара. «Отложить» пропускает пару до перезагрузки.
- **Сбросить все решения по парам** удаляет все решения, ручные и автоматические,
  после подтверждения. «Разные люди» возвращаются сразу; слитые люди разделятся
  при следующей сборке сущностей (шаг 3). Необратимо.

## Интерфейс

- Под заголовком каждой страницы — кнопка «Как это работает»: пояснение и
  следующее действие.
- Светлая и тёмная тема — по настройке системы.
- На телефоне меню открывается кнопкой в верхней панели; таблицы прокручиваются
  внутри себя, имя в «Людях» остаётся на месте.
- «К содержанию», видимая рамка фокуса, подписи полей и таблиц.
- Нумерация страниц: «Назад · 1 · … · 12 13 14 · … · 248 · Вперёд», фильтры
  сохраняются.
- Имена — фамилией вперёд («Иванов Иван Петрович»).

Для диаграмм вики в образ ставятся `plantuml` и `graphviz`. Локально
(`uv run`) нужны те же пакеты: `sudo pacman -S plantuml graphviz`. PDF вики
(`/ui/wiki/export.pdf`) собирается ~15 с.

## Проверка

```bash
TEST_DATABASE_URL=postgresql+psycopg://court_monitor:court_monitor_test@127.0.0.1:5434/court_monitor_test \
  uv run pytest tests/app
```

`tests/app/test_investigator_ui.py` проверяет, среди прочего, что число запросов
досье не растёт с размером дела, порядок хронологии, лимит графа, экранирование
загруженного текста и старые адреса.

## Ограничения и типичные ошибки

- Страницы только читают, кроме форм: шаги pipeline, решения по парам и
  безымянным, исправление имени, отметка должностного лица, сброс решений.
- Счётчик очереди в меню пересчитывает спорные пары по всей базе на каждой
  странице.
- «Отложить» не хранится в базе.
- JSON API (`/persons`, `/articles`, `/search`, `/operations/runs`, …) консоль не
  меняет; он остаётся контрактом для автоматизации.
