# Junk Screen / Отсев мусора с проверкой

## Зачем это нужно

Шаг 2 «Очистить от мусора» удаляет статью, если rule-based извлечение не нашло в ней
уголовного события (задержание, арест, обыск, обвинение, возбуждение дела, приговор), и
стирает её текст навсегда. Правила иногда ошибаются: сводки новостей, непривычные
формулировки. По замеру на 20 993 статьях так терялось около 11% удаляемых статей с
юридическими словами — около 490 статей о делах.

Отсев — модель на embeddings, которая перед удалением оценивает статью. Похожие на новость
об уголовном деле она **удерживает на проверку** человеку, а не удаляет. Высокая оценка — не
доказательство дела: удержанная статья не идёт дальше по конвейеру, пока в ней не найдено
событие.

В коде по умолчанию **выключен**; `compose.yaml` включает его для API (`JUNK_SCREEN=1`).

## Быстрый сценарий

1. Включить (нужен образ с группой `semantic`, см. ниже) и запустить шаг 2:

   ```bash
   docker exec -e JUNK_SCREEN=1 ebnv-api-1 sh -c 'cd /app && /opt/venv/bin/python src/main.py purge-junk'
   ```

   Чтобы шаг 2 на «Управлении» тоже шёл с отсевом, задать `JUNK_SCREEN=1` в окружении
   сервиса `api` и пересоздать его.
2. Карточка запуска показывает «Оставлено на проверку: N»; итог в выводе команды — `held`.
3. «Очередь» → «Отсев на проверке» (`/ui/junk-holds`): статья, оценка и порог, какие события
   нашло извлечение, почему удержана.
4. Дело есть — исправить правила извлечения (`src/extraction/events.py`), пересобрать образ
   и нажать «Извлечь заново». Найденное событие вернёт статью в работу: её возьмёт следующая
   сборка людей. Правила не менялись — повторять нечего, страница так и скажет.
5. Дела нет — «Мусор»: статья удалится при следующей очистке. До этого можно «Вернуть на
   проверку».

## Как устроено

- Модель: `intfloat/multilingual-e5-base`, embedding «заголовок. первые 1 500 символов»;
  логистическая регрессия поверх него (`src/monitoring/junk_screen_model.json`). Порог
  0,5202 выбран на калибровочной части размеченной выборки.
- Замер на отдельной проверочной части: из 63 дел, которые правило удалило бы, отсев
  удерживает 51 (81%); из 105 удержанных 54 — мусор (точность 0,49). Подробно —
  `reports/junk_screen_2026-09-27.md`.
- Удержанная статья (`junk_screen_holds`, статус `held`) не удаляется очисткой — ни с
  отсевом, ни без него — и повторно не оценивается. «Мусор» (`junk`) — удаляется следующей
  очисткой без новой оценки.
- Статьи до `PIPELINE_SINCE` удаляются по дате, удержанные тоже.

## Безопасность

- Отсев включён, но файла модели нет, он испорчен, модель embeddings не загружается —
  `purge-junk` падает **до** первого удаления.
- Модель упала посреди очистки — текущая порция не удаляется и не удерживается, команда
  падает. Удалённое прежними порциями остаётся удалённым (как и без отсева).

## Кодовые точки входа

- Оценщик: `src/monitoring/junk_screen.py`; загрузка модели embeddings (sentence-transformers,
  префикс E5 `passage: `, `EMBEDDING_DEVICE`, `EMBEDDING_BATCH_SIZE`):
  `src/monitoring/embedder.py`; очистка: `src/monitoring/junk_purge.py`.
- «Мусор» / «Извлечь заново»: `src/monitoring/junk_holds.py`; страница:
  `src/web/ui/junk_holds.py`.
- Замер и переобучение: `src/evaluation/junk_screen/` (корпус из дампа до очистки,
  разметка моделью, сравнение способов, экспорт модели); метки —
  `evaluation/junk_screen/labels.json`.

## Ограничения и типичные ошибки

- Нужен образ с `INSTALL_SEMANTIC=1` (torch, sentence-transformers; `compose.gpu.yaml`
  его собирает); без них включённый отсев упадёт до удаления с `JunkScreenError`.
- Разметка сделана моделью (DeepSeek) и проверена выборочно; в проверочной части всего 63
  дела — оценки грубые (полнота 0,70–0,89).
- Пропускает сводки новостей («Главные новости к вечеру»), удерживает зря давние дела
  политзаключённых (условия содержания), шаблонные сообщения СК, иностранные новости.
- Модель обучена на статьях до 16.09.2026: при смене источников — перекалибровать.
