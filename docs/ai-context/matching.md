# Сопоставление людей (Matching)

## Обзор

Система сопоставляет факты `full_name_original` из судебных документов с записями `PersonRecord` (Росфинмониторинг). **Никогда не подтверждает автоматически** — только создаёт кандидатов для оператора.

## Нормализация имён (name_normalizer.py)

Морфологическая нормализация `ru-name-v2` — склонения → именительный падеж:

| Исходное | Нормализованное |
|---|---|
| Иванова Ивана Ивановича | Иванов Иван Иванович |
| Петрову Марию Сергеевну | Петрова Мария Сергеевна |

Детекция пола по окончанию отчества (`-вич` → m, `-вна` → f). Три набора правил: фамилии (m/f), имена (m/f), отчества.

### Порядок токенов в двусловных именах

Трёхсловное ФИО заякорено отчеством, поэтому фамилия заведомо идёт первой. У двусловного якоря нет, и две стороны системы расходятся: новостной текст пишет «Владимир Романов» (имя первым), а реестр РФМ — «Романов Владимир Петрович».

Раньше `_simple_parse` безусловно брал `tokens[0]` как фамилию, из-за чего имя из статьи попадало в поле `surname` и surname-индекс не мог совпасть с записью **никогда**. На живом корпусе 367 из 463 person-фактов были двусловными; попаданий по фамилии: 6 (первый токен) против 83 (последний).

Порядок определяется по самим токенам, по убыванию надёжности сигнала:

1. `_GIVEN_NAMES` — список ~147 распространённых русских имён. Нужен там, где суффиксный тест бессилен: в «Ирина Иванова» оба токена выглядят как фамилия (`-ина` / `-ова`).
2. `_SURNAME_SUFFIXES` — характерные окончания (`-ов/-ев/-ин/-ский/-енко/-дзе/-швили/-ян/-оглы` и женские формы). Разрешает и косвенные падежи («Виктора Алексеенкова»).
3. При одинаковом сигнале с обеих сторон сохраняется прежнее поведение «Фамилия Имя» — неоднозначная пара не становится хуже, чем была.

Правило симметрично, поэтому вход в порядке реестра («Иванов Иван») не ломается.

## Pre-filtering

Surname-based: строится индекс `normalized_surname → list[PersonRecord]`. Для каждого facts берутся только записи с совпадающей фамилией — избегает O(N*M).

## Формула score (score.py)

| Правило | Вес |
|---|---|
| Полное совпадение ФИО (morphological) | +0.70 |
| Совпадение фамилии и имени | +0.50 |
| Совпадение фамилии и инициалов | +0.35 |
| Совпадение даты рождения (full date) | +0.20 |
| Совпадение года рождения | +0.15 |
| Совпадение места рождения | +0.10 |
| Конфликт года рождения | -0.60 |
| Конфликт даты рождения | -0.50 |
| Конфликт имени/фамилии | -0.40 |

Порог создания кандидата: `score ≥ 0.45`. Алгоритм: `match-v3`.

## BirthDateEvidence

Тип `BirthDateEvidence` (dataclass) отличает full date от year-only:

- `precision="full"` — год + месяц + день
- `precision="year"` — только год (не fabrication month/day)
- `precision="none"` — нет данных

Извлечение из `fact.quote`: паттерны `(\d{4}) года рождения`, `(\d{4}) г.р.`, `рожд. (\d{4})`, полная дата `DD месяц YYYY`.

## Почему на практике все кандидаты равны 0.50

Порог 0.45 проходит только совпадение фамилии **и** имени (0.50). Дальше скоринг сказать нечего: `_score_birth_date` и `_score_birthplace` написаны и протестированы, в реестре даты есть у 21 511 записей из 21 511 — но в текстах документов их нет (замер: 5 упоминаний даты рождения на 379 документов, мест рождения — 0). Подробности и причина в `known-risks-and-notes.md`.

Поэтому различить человека от однофамильца алгоритмически нельзя, и карточка кандидата в вебе показывает то, что скор выразить не может:

- `repo.count_registry_namesakes` — сколько записей реестра носят ту же фамилию. Один Шульман и 64 Иванова при одинаковом 0.50 — принципиально разные сигналы.
- `repo.find_other_mentions` — упоминания того же человека в других документах, с цитатами. Фигурант нескольких материалов — не то же самое, что единичное упоминание.

## CLI

```bash
court-monitor generate-matches          # генерация кандидатов
court-monitor list-matches              # список
court-monitor list-matches --status pending  # фильтр
court-monitor show-match <id>           # детали с объяснением
court-monitor confirm-match <id> --comment "..."
court-monitor reject-match <id> --comment "..."
```
