# Экспорт справочников из Airtable

Здесь оператор складывает выгруженные из Airtable CSV, когда база доступна только для
просмотра (публичная ссылка) и API-токен получить нельзя. Подробности и сравнение двух
режимов — [docs/wiki/Airtable-Sync.md](../docs/wiki/Airtable-Sync.md).

## Как пользоваться

1. Откройте нужную таблицу по публичной ссылке в браузере.
2. Нажмите **Download CSV** (в Airtable: `Share` → `Download CSV`, либо значок в правом
   верхнем углу представления).
3. Положите файл сюда под именем таблицы:

| файл | справочник | обязательные столбцы |
|---|---|---|
| `sources.csv` | Источники | `base_url` (он же `Ссылка`, `Адрес`, `URL`) |
| `rfm_persons.csv` | Росфинмониторинг | `full_name` (он же `ФИО`, `Преследуемый`, `Имя`) |
| `known_persons.csv` | Найденные люди | `full_name` |
| `excluded_persons.csv` | Исключения | `full_name` |

4. На странице **«Справочники»** нажмите «Синхронизировать Airtable».

## Что важно знать

- **Пустой файл не трогает данные.** Файл, в котором есть только заголовок, будет
  отклонён с ошибкой, а не прочитан как «список пуст»: иначе одна ошибка выгрузки
  стёрла бы весь перечень РФМ. Отсутствующий файл просто пропускается.
- **Токен не нужен.** В этом режиме Airtable вообще не опрашивается.
- **В CSV нет идентификатора записи Airtable.** Для перечня это не важно — записи
  сопоставляются по паре ФИО + дата рождения. Для «найденных людей» и «исключений»
  сопоставление идёт по ФИО, поэтому если ФИО человека поменяют, появится вторая
  строка, а не обновление.
- **Обновление не автоматическое.** Файл выгружается руками каждый раз. Для перечня,
  который меняется редко, это скорее плюс.
- **Файлы не попадают в git.** `*.csv` здесь игнорируется; в репозитории лежит только
  эта папка и её README.

## Как выгружать

Возьмите у реальной базы «ЕНБВ» (публичная ссылка, без токена):

| что выгрузить | файл | колонки, которые нужны |
|---|---|---|
| Источники | `источник мониторинга(1).csv` → `sources.csv` | `Ссылка`, `Название` — все 69 совпадают с реестром кода |
| Перечень РФМ | `ЕНБВ. Кейсы по персоналиям.csv` → `rfm_persons.csv` | `Преследуемый`, `Дата рождения`, `✦Росфинмониторинг` |
| Исключения | `excluded_persons.csv` | `ФИО`, `Категория`, `Причина` |
| Найденные люди | `known_persons.csv` | `ФИО` |

Колонки можно оставить все 72 — лишние игнорируются, нужен только порядок имён.

**Про перечень.** В исходном файле одна строка на дело, а не на человека: 14 306 строк
про 13 765 человек. Импортер сам оставит по одной записи на человека. Строки **без
отметки** `✦Росфинмониторинг` в перечень не попадут.

**Даты.** `Дата рождения` в выгрузке приходит как `July 12, 1980`. Импортер это
понимает. Но если вы выгрузите представление с другими настройками и дата окажется в
незнакомом формате — проверьте результат: в отчёте будет `с датой рождения` заметно
меньше, чем людей.
